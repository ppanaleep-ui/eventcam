# 🚀 นำเว็บขึ้นออนไลน์ (Deploy)

ตอนรันในเครื่องตัวเอง (`localhost`) มีแต่คุณเข้าได้ พอถึงวันงานจริงต้องให้แขก
สแกน QR แล้วเข้าจากมือถือที่ไหนก็ได้ — ต้องเอาเว็บขึ้น "ออนไลน์" ก่อน

หน้านี้มี 2 วิธี เรียงจากง่าย-ตรงไปตรงมาที่สุดสำหรับระบบนี้

---

## ⭐ วิธีที่ 1 (แนะนำ): Docker บนเซิร์ฟเวอร์ของคุณเอง

ระบบนี้ใช้ **ฐานข้อมูล SQLite + เก็บรูปในดิสก์ + แจ้งเตือนสด (SSE)** ซึ่งทำงานได้ดีที่สุด
เมื่อรันเป็น **เซิร์ฟเวอร์เดียวที่มีดิสก์ถาวร** — Docker ตอบโจทย์นี้พอดี

### สิ่งที่ต้องมี
- เครื่องเซิร์ฟเวอร์ (VPS) สักตัว หรือคอมที่เปิดทิ้งไว้ได้ ที่ลง **Docker** แล้ว
  (ติดตั้ง Docker: https://docs.docker.com/get-docker/)

### ขั้นตอน
1. ก๊อปโปรเจกต์ขึ้นเซิร์ฟเวอร์ (เช่นผ่าน `git clone` หรือ copy โฟลเดอร์ไป)
2. สร้างไฟล์ `.env` และตั้งค่า 2 อย่างที่สำคัญ:
   ```env
   SESSION_SECRET="<รันคำสั่ง npm run gen:secret เพื่อสร้าง>"
   NEXT_PUBLIC_APP_URL="https://your-domain.com"
   ```
   > `NEXT_PUBLIC_APP_URL` ต้องเป็น URL จริงที่แขกจะเข้า เพราะ QR code สร้างจากค่านี้
3. สั่งรันด้วยคำสั่งเดียว:
   ```bash
   docker compose up --build -d
   ```
4. เปิด `http://<ไอพีเซิร์ฟเวอร์>:3000` — ถ้าขึ้นหน้าเว็บ = สำเร็จ ✅

### ข้อมูลไม่หาย
`docker-compose.yml` ตั้ง **volume** ไว้ 2 อัน:
- `db` → เก็บฐานข้อมูล (คำอวยพร, ซอง)
- `uploads` → เก็บรูปภาพที่แขกอัปโหลด

ข้อมูลจะอยู่ครบแม้รีสตาร์ท/รีบิลด์คอนเทนเนอร์

### ทำให้เป็น https + โดเมนสวย
แนะนำวาง **reverse proxy** ไว้หน้าเว็บเพื่อทำ HTTPS อัตโนมัติ เช่น
[Caddy](https://caddyserver.com) (ตั้งค่าไม่กี่บรรทัดก็ได้ https ฟรีจาก Let's Encrypt)
หรือ Nginx + Certbot

> 🔎 ตรวจสุขภาพระบบได้ที่ `https://your-domain.com/api/health` → ควรได้ `{"status":"ok"}`

## วิธีที่ 2 (ขั้นสูง): Vercel / แพลตฟอร์ม Serverless

Vercel กด deploy ง่ายก็จริง แต่ระบบนี้ **ต้องแก้เพิ่ม 3 จุด** ก่อน เพราะ serverless
ไม่มีดิสก์ถาวรและรันหลายอินสแตนซ์:

1. **ฐานข้อมูล** — เปลี่ยนจาก SQLite เป็น **Postgres** (เช่น Neon, Supabase, Vercel Postgres)
   - แก้ `prisma/schema.prisma` บรรทัด `provider = "sqlite"` เป็น `"postgresql"`
   - ตั้ง `DATABASE_URL` เป็น connection string ของ Postgres
   - รัน `npx prisma migrate deploy`
2. **ที่เก็บรูป** — เปลี่ยนจากดิสก์ (`storage/`) เป็น cloud เช่น **S3 / Cloudflare R2 / Vercel Blob**
   - แก้ฟังก์ชัน `saveImage` ใน `src/lib/uploads.ts` ให้อัปโหลดขึ้น cloud แล้วคืน URL
3. **แจ้งเตือนสด (SSE)** — เปลี่ยน `src/lib/events-bus.ts` จาก in-memory เป็น **Redis pub/sub**
   หรือบริการ realtime (เช่น Pusher/Ably) เพราะ serverless แต่ละครั้งเป็นคนละโปรเซส

> สรุป: ถ้าอยากได้ระบบครบ-พร้อมใช้ **โดยไม่ต้องแก้โค้ด** ให้ใช้วิธีที่ 1 (Docker)
> วิธีที่ 2 เหมาะเมื่อคาดว่าคนเข้าพร้อมกันเยอะมากและต้องการสเกลแนวนอน

## ตั้งค่า Environment Variables บนเซิร์ฟเวอร์จริง

ไม่ว่าจะวิธีไหน ให้ตั้งค่าเหล่านี้ (ห้ามใช้ค่า dev เดิม):

| ตัวแปร | ใส่อะไร |
| --- | --- |
| `SESSION_SECRET` | ข้อความสุ่มยาว ๆ (จาก `npm run gen:secret`) |
| `NEXT_PUBLIC_APP_URL` | URL จริงของเว็บ เช่น `https://wish.example.com` |
| `DATABASE_URL` | ที่อยู่ฐานข้อมูล (Docker ตั้งให้แล้ว / Vercel ใส่ของ Postgres) |
| `SLIP_VERIFY_PROVIDER` | `easyslip` ถ้าจะเปิดตรวจสลิป (ไม่งั้นเว้นว่าง) |
| `EASYSLIP_API_TOKEN` | token จาก EasySlip |

> ⚠️ ห้าม commit ไฟล์ `.env` ขึ้น git เด็ดขาด — โปรเจกต์ตั้ง `.gitignore` กันไว้แล้ว
> บนแพลตฟอร์มจริงให้ใส่ค่าผ่านหน้า "Environment Variables" ของผู้ให้บริการ
